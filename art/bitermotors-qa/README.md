# Biter Motors Artwork QA

Development-only static artwork inventory generated by
`scripts/build-bitermotors-art-qa.py`. It is not included in Factorio release
archives. Browser approve/revise decisions only record a local static review;
they are not evidence of native in-game review or release approval.

The critical inventory follows the asset families in
`docs/v1-readiness-review.md` (minimum asset matrix / R15) and the current
prototype and art references in `mod/bitermotors_0.1.1/data.lua`. The manifest
uses stable prototype-based review IDs and records source dimensions, preview
dimensions, and Factorio scale when a bitmap exists. Generation fails when a
required local bitmap or icon is missing or invalid.

Inherited art is explicitly marked. Tandem Solar Array reuses the High-density
Solar placed bitmap; Grid Battery Array reuses Grid Battery art. Orbital
Radiator and Space Solar both inherit the vanilla solar-panel picture and are
currently visually identical in-world. This is a known pending R15 defect, not
an approval. eSpider uses inherited tinted vanilla Spidertron art; the
Cybertrain and charging stop use their local directional/rail previews. Dataset
and AGI Model are inventory items, so they have icons but no placed-entity art.

The 27 critical records include the Bitertaxi Depot. Supporting icon, animation,
and technology reviews also use filename-based IDs rather than array positions.
Animation previews are bounded to their cards, including the large factory sheets.

Run `python3 scripts/build-bitermotors-art-qa.py` to regenerate the index and
manifest. The page previews assets and supporting icon/animation/technology
inventories; it cannot establish native entity scale, animation gating,
selection boxes, night/remote-view readability, UI fit, or sound. Those still
require the isolated native showcase review described by the readiness review.
